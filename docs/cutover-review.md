# 指名検索の保存・復元：ローカル確認版

この文書と `src/cutover.py` は本番切り替え前の確認用です。ローカルでは[手動リハーサル](rehearsal.md)への接続まで準備していますが、会社GitHubへは未反映です。既存のGSC取得比較CLIは引き続き読み取り専用です。

## 対象と順序

- **検証用Sheetだけ**を更新・復元対象にします。元シートIDはコードで拒否します。対象IDと3タブのID、タイムゾーンを毎回確認します。
- GSC取得候補を既存の検証で照合し、既存期間の差があれば停止します。
- 更新前の3タブ全履歴をgzip JSONにし、専用フォルダへ**新規作成**します。Driveから読み戻してバイト列、構造、件数、集計、指紋を検証します。
- 元シートを再読込して全履歴の指紋が変わっていないことを確認し、3タブを1回のSheets `batchUpdate`で書きます。書式は変更せず、値のみ更新します。
- 全件を読み戻して候補と一致した場合だけ更新後バックアップを新規作成・再読込し、実行記録も保存・再読込します。
- 応答が途切れた書込は再送しません。読み戻しで更新前・候補・その他のどの状態かを判定し、候補と一致する場合だけ先へ進みます。更新後バックアップが失敗しても自動で元に戻しません。

## 復元

選んだ世代のID・タブ構造・全件指紋を確認します。現在の3タブ全履歴を別世代として退避・再読込した後、検証用Sheetへ3タブ一括復元し、全件を読み戻します。復元先のSheet IDは維持します。定期実行停止、世代選択、実シートへの復元、ページ再生成はこの版では実行しません。

## バックアップの中身と限界

各runの `before.json.gz`、`after.json.gz`、`manifest.json` はすべて新規ファイルです。JSONには検索語を含む全履歴、見出し、対象Sheet・タブID、タイムゾーン、実行ID、コード版、日時、件数、集計、全件指紋を記録します。Drive接続は専用フォルダへの新規作成と同フォルダからの読取だけを実装し、更新・削除・権限変更はありません。通信断後の新規作成は重複防止のため自動再試行しません。

このバックアップは、元Sheetの値の誤更新から戻すためのものです。**書式を含む初回Sheet全体コピー、旧GASコードとトリガー仕様の保存、会社Driveの権限・保存先の作成、実アカウントでのリハーサルは別工程**です。同じ共有Drive内の保存なので、改変不能な別系統バックアップにはなりません。管理者の削除やDrive全体の障害には備えられません。

## 確認結果と次の区切り

合成データによる正常更新・復元、既存期間の差、元データの途中変更、バックアップ読戻し失敗、書込後の通信断、更新後バックアップ失敗、対象外フォルダ、元Sheet拒否をテストします。保存済み元データ570日・検索語9,607行の圧縮／読戻しもローカルで検査します。生データ・認証値はリポジトリやレポートへ入れません。

次に進むには、この確認版と具体的な作成先・権限差分を確認した上で、会社Driveに専用フォルダと検証用Sheet・バックアップIDを準備し、**本番シートに書かないリハーサル**を行います。副担当は未定のまま記録します。
